# 任务拆解与执行顺序

> 题源：10 月数媒程序开发组考核 ——《医院门诊号源预约与候补系统》
> 本文档是任务总纲。每一轮对话只做其中一批，做完更新 `PROJECT_STATE.md`。

---

## 0. 一句话定义

给三甲医院热门科室做一个号源预约演示系统，核心是 **号源有限 + 候补自动递补 + 实名校验**：
既不能让一个号被多人占用，又要在患者取消时把空号及时递补给排队的第一位。

---

## 1. 技术栈（已确定）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.13 + FastAPI + Uvicorn | 语法轻、自带交互式接口文档，答辩时可以直接在 `/docs` 演示调接口 |
| 数据库 | SQLite（`data/clinic.db` 单文件） | 文件即数据库，天然满足「重启不丢」；支持部分唯一索引，防重约束能落到库层面 |
| 前端 | 原生 HTML / CSS / JS | 无构建步骤，双击即开；代码全在明面上，答辩能逐行解释 |
| 测试 | pytest + httpx + threading | 并发用例用线程池同时打同一个接口 |

启动方式（最终形态）：

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
python -m uvicorn app.main:app --reload
# 浏览器打开 http://127.0.0.1:8000
```

### R3 · 预约、候补与自动递补（核心轮）
**目标**：把 `预约 → 入候补 → 退号 → 转正` 四个动作做成一个原子流程。

| 交付文件 | 说明 |
|---|---|
| `app/services/booking.py` | `create_booking()` / `cancel_booking()`，全部在单事务内完成 |
| `app/routers/appointments.py` | 预约、取消、我的预约/候补 |
| `app/services/guards.py` | 三条防黄牛校验，集中在事务内调用 |

**验收**（手工 + 脚本双重）：
1. 有余号 → 立即成功并拿到序号；
2. 无余号 → 变成候补第 N 位，返回排队号；
3. 取消一个正式预约 → 候补第 1 位在同一事务内变正式，并**继承空出的那个序号**；
4. 同一人同时段重复预约 → 被拒；
5. 同一人同天同科室第 2 个号 → 被拒。

**R3+ 补漏**（本轮收工前追加，详见 `PROJECT_STATE.md`）：
递补顺延（P0）、统一 422（P1）、`DELETE /api/waitlist/{id}`（P1）、过去日期校验（P2）、
抢到号自动出队（附带），外加 23 条单测落盘。

## 3. 全局约定（每轮都必须遵守）

1. **状态只有一处计算**：剩余号、号源状态一律由 `services/slot_status.py` 产出，前端与其它后端模块不得自行推导。
2. **写操作必须走事务**：所有改号源的动作用 `BEGIN IMMEDIATE`，先校验再写，最后用受影响行数确认。
3. **不做真实鉴权**：只认 `X-User-Id` 请求头，登录接口是模拟的。README 里要主动说明这一取舍。
4. **状态一律用后端给的 `status_label`，前端不自己拼中文**，避免两边文案不一致。
5. **拼进 HTML 的数据必须先转义**：用户姓名是登录时自由填写的，不转义就是存储型 XSS。
4. **注释规则**：只给新代码加注释，不改动已有注释；事务性函数必须写明「为什么这样写才安全」。
5. **错误返回统一**：`{"ok": false, "error": {"code": "...", "message": "..."}}`，业务码见 `API.md`。
   **这个形状没有第二种** —— 框架自己抛的 422 也被收编成 400 `INVALID_PARAM`（R3+ 已实现）。
6. **中文界面**：所有用户可见文案用中文。
7. **递补必须重跑规则**：候补队列是延迟求值的检查点，出队时的状态与入队时可能已经不同。
8. **并发正确性靠数据库那把锁**，不靠"代码写得小心"：条件 UPDATE + `BEGIN IMMEDIATE` + 唯一索引，三层各挡一种失效。任何"先查再写"的写法在并发下都是错的。
9. **默认隐藏的信息必须能显式取回**：过去日期的排班默认不出现在列表里（`only_future=1`），但一条都不删，且留了 `only_future=0`。只对当下便利负责而不留出口，就是把便利变成欠账。
10. **测试也要被测试**：一致性测试之外要跑变异测试，把故意改坏的版本送进去，验证检查确实会变红。一个从没红过的测试，没人知道它在不在测东西。
11. **时间与阈值各自只有一处来源**：数字一律放 `services/policy.py`，"现在"一律取 `services/clock.py`，不许在业务代码里写魔法数字或直接写 `datetime('now','localtime')`。
12. **结构升级走迁移，不靠重建**：改表结构要同步 `db.ensure_up_to_date()` 的迁移逻辑，保证已有库平滑升级且一条数据不丢。迁移必须写成幂等的 —— 没人能保证它只被执行一次。
13. **依赖结算结果的判断，必须与结算本身分开提交**：同一个事务里先结算再抛异常，会把结算一并回滚，于是"刚刚作废的号"又活了过来。

## 4. 已知风险点

| 风险 | 处理方式 |
|---|---|
| `seq_no` 用 `MAX+1` 会越界 | 改为「1..total 中取最小未占用号」，见 `DATA_MODEL.md` 决策 3 |
| SQLite 并发写锁超时 | 连接串加 `timeout=5`，写事务用 `BEGIN IMMEDIATE` 提前拿锁 |
| 并发测试在单线程 TestClient 上测不出问题 | 用真实 uvicorn + httpx 并发请求，不用 TestClient |
| 状态字段与计数不一致 | 计数只由事务内的 `+1/-1` 维护，状态永远派生不落库 |
